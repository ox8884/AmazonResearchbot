# 시장 비교 근거

Jay가2026-09-09 선택한 시장점유1위 가격의 비교 범위는 Jungle Scout 상품 DB 전체 조회 결과다. Amazon 첫 페이지 자료와 혼합하지 않는다.

상품 DB의 페이지를 모두 수집한 뒤 고유 ASIN마다 같은 anchor로 Sales Estimates의 명시적인30일 구간을 요청한다. 카탈로그에 월 매출 추정치가 있어도 이 단계를 생략하지 않는다. 중복 ASIN은 한 번 조회하며, 날짜·가격·판매량과 상품 식별자는 기존 응답 검증을 거친다.

공통 기간의 판매량·매출은 해당 일별 자료로 교체한다. 빈 응답, 누락된 날짜, 유효하지 않은 값은 이전 카탈로그 추정치로 메우지 않는다. 카탈로그와 판매 응답의 family 식별자가 충돌하면 미확인으로 남긴다.

변형 상품은 부모 ASIN도 같은 구간으로 조회한다. 부모 응답이 자신을 부모 상품으로 식별하고 해당 자식을 목록에 포함한 경우에만 부모의 매출 추정을 상품군 기준으로 사용한다. 같은 부모는 한 번만 조회하며 자식 매출을 더하거나 중복 상품군으로 세지 않는다. 소속 또는 부모 매출을 확인할 수 없으면 미확인이다.

단독으로 가장 높은 양수 매출 상품군을 선택한다. 전체 조회가 불완전하거나 매출이 미확인·상충하거나 공동1위이면 가격을 확정하지 않는다. 1위 상품군 안에서도 조회된 가격이 모두 확인되고 일치할 때만 해당 카탈로그 가격을 추정 근거로 연결한다. 단순 검색순위나 자식 매출 합계를 사용하지 않는다.

가격·상품군·가격 비교 ASIN·비교 기간은 공식 평가와 같은 트랜잭션에 기록한다. 새 공식 평가에서 가격이 미확인이면 이전 수동 가격을 대신 쓰지 않는다. 화면은 추정/미확인을 구분하고 비교 범위와 기간을 보여준다.

최종 저장 직전 후보·기준 잠금 안에서 규격과 차별화 근거를 다시 읽는다. 조회 도중 이 근거가 달라졌다면 가격·평가·단계 변경을 기록하지 않고 stale을 반환한다. 새 근거의 재검증은 보존된 API cache를 재사용할 수 있다. 이번 조회에서 새로 계산한1위 가격은 이전 canonical 가격과 비교하지 않는다.

모든 요청은 기존 계정별 cache, 예산 예약, 호출 상한, 속도 제한, 재시도·불확실 결과 보호를 통과한다. 실제 활성화 시 필요한 호출 수는 고유 ASIN 및 부모 상품군 수에 따라 증가하며, 한도가 부족하면 대기하고 재개 시 같은 구간의 cache를 재사용한다. 이번 구현은 유료 호출의 승인이 아니다.

공통기간 수집·1위 가격 판정·canonical top_price 연결은 구현·로컬 검증·메인 반영됐다. 실제 유료 제공자 응답 인수, 차별화 근거 연결, 전체 무인 인수는 별도 미완료 작업이다. 이 가격은 API 자료에 기반한 추정이며 실제 수익성 확인을 뜻하지 않는다.

검증 명령: `pnpm verify:local -- --scenario api-validation`. 기존 API 수집·캐시·후보·재실행 검증과 함께1위 가격 선택 및 실제 로컬 통합 흐름을 실행한다. 공동1위, 부모 매출, 가격 충돌, 저장 rollback, 조회 중 근거 변경도 포함한다. 모든 하위 검증은 실제 제공자 전송을 비활성화하며, 이 명령의 PASS는 실제 유료 API 또는 전체 overnight 인수의 PASS가 아니다.

추가 시장 확인의 구현은 별도다. 실제 Amazon 첫페이지의 비광고 고유ASIN을 공통30일로 조회하고 부모상품군을 한 번씩만 계산한 총매출과1위/상위3 점유율을 worker 평가payload에 연결했다. 누락/충돌은 미확인, 확인된 총매출0의 비율은 미확인이다. 비교 범위는 첫페이지 상품군이며 전체 Product Database 기준1위가격과 혼합하지 않는다. 판정은 반올림 전 비율로 하고 기존4/5 니치판정을 바꾸지 않는다. 후보 화면은 저장된 기간·적용기준·근거종류와 주의/미확인/이전값을 표시하며 KO/EN·3폭의 격리 UI 검증을 통과했다. 최종발주판단 연결과 메인 실행갱신은 아직 남아 있다.
